# 软件指南生成器

macOS 原生 App：输入软件名称和功能要求，自动规划界面、调用模型生成界面示意图、撰写说明文字，导出 Word / PDF / TXT 指南；配置自己的代码来源后也能排版代码文档。支持单个项目精修和批量处理。

[下载](https://github.com/deepfry666/ruanzhu-guide/releases) · [快速入门](docs/快速入门.md)

> 应用里称为「截图」的图片是 AI 生成的界面示意，不是实际运行软件的截屏，也不能证明功能已实现。文字、日期、代码来源和导出材料都需要人工核验。

## 功能

| 工作 | 功能 |
| --- | --- |
| 从需求到初稿 | 规划界面，生成配图，用看图模型验收并抄录图中文字，撰写说明，可附加设计说明 |
| 逐屏修改 | 图片和文字并排编辑；每屏一个「修改」入口，选择图和文字或只改文字，查看与恢复历史版本 |
| 交付文件 | 导出指南 Word / PDF / TXT；配置代码来源后生成代码文档 |
| 批量处理 | 批量新建、按名单选择、只重写文字、全部重做、批量更新代码材料与导出 |
| 追踪过程 | 项目进度、调用记录和统计；「已提交」标记让项目保持只读 |

侧边栏为「项目、模型与线路、统计、设置」，用 ⌘1～⌘4 切换。在「项目」工具栏点击「新建」，或在任意页面通过「文件 → 新建项目」（⌘N）打开弹窗，选择「单个」或「批量」。

## 使用前准备

- **系统**：macOS 26 或更高，仅 Apple 芯片（arm64）。
- **模型服务**：自备生图线路和大模型 API。下载应用不含模型额度，生图、规划、验收、写文字都可能由服务商计费。
- **LibreOffice**：指南 PDF 转换需要另外安装。
- **代码与字体**：代码模板和商业字体不随安装包提供。

安装包采用 ad-hoc 签名，首次打开可能需要在「系统设置 → 隐私与安全性」里放行。之后可在软件里「检查更新」在线升级。

## 数据

- 项目默认保存在 `~/Desktop/软件指南生成`，可在设置里更改。
- 设置、调用记录和密钥保存在 `~/Library/Application Support/软件指南生成器（原生版）`。
- AI 步骤会把所需文字或图片发送给你配置的模型服务商。不要提交 API 密钥、应用数据目录或调用日志。

## 从源码构建

需要 Xcode 27（macOS 27 SDK）。

```bash
cd native
scripts/build-app.sh --zip     # 生成 dist/软件指南生成器.app 和 zip
```

也可以用 Xcode 打开 `native/ManualStudio.xcodeproj` 开发。发版：`native/scripts/release.sh <版本号> [更新说明文件]`。

### 试用环境

运行 `native/scripts/trial.sh` 编译并启动独立的「试用」包，默认复制最近完成的 3 个项目；正式包与正式数据不变。用 `--count 5` 调整数量，或重复 `--project <项目文件夹>` 指定项目。`--name <字母数字名字>` 为并行任务隔离数据与偏好，`--reset` 重新准备该名字的副本（须先退出试用版）。

验证前运行 `native/scripts/trial.sh --snapshot`，退出试用版后运行 `native/scripts/trial.sh --verify`，应输出「无差异」。核对覆盖正式数据目录与整个正式工作区；正式版自身的运行也可能产生差异。`--measure` 单独准备全部状态和索引（项目只建空文件夹），仅显示列表，不复制项目内容、密钥、队列或调用记录；不允许打开项目或执行步骤。不要直接打开构建包，始终用脚本启动；试用版禁用更新。试用数据含私人项目及密钥，保存在应用程序支持目录下独立的「试用」文件夹内，不要上传。AI 步骤仍须事先获得授权；本机验证只运行 receipt、build。

开发测量可设置 `MS_DEV_CONTROL=<仓库外指令文件>` 后启动试用脚本。在指令文件里逐行写 `section=projects`、`stress=<每秒事件数>`、`scroll=1`、`probe=<仓库外结果文件>`，分别控制列表、模拟事件、自动滚动和延迟采样；用 `probe=stop` 写出统计，`stress=0`、`scroll=0` 停止模拟与滚动。自动滚动只在试用版生效，不调用 AI 或修改项目文件。试用版或开发控制启用时，标准错误输出包含读文件、解析、摘要、索引与设置和界面替换的耗时。结果和截图保存在仓库外。

### 交付包自动更新

保存文字或 TXT 字段后，若只差本机步骤，约 3 秒后自动更新 Word、TXT 和 PDF，并检查 PDF 排版。连续保存会重新计时。更新时保留已完成分组，不计入项目运行用时。需要重新检查截图等 AI 步骤时，项目页显示原因和「继续」，由你决定是否运行。

无需再按「检查并更新」或「重新导出 PDF」；⌘R 可手动检查。打开交付文件、导出或打包 zip 会先等待更新，仍需 AI 的项目会被阻止或列入跳过清单。失败时查看项目页原因并点「重试」。交付包中手改的 Word / TXT 会先另存到 archive 的「手改保留」文件夹，再覆盖，并在项目页提示。退出时会等待本机更新结束。

项目列表按「需要处理 / 进行中 / 已完成 / 已提交」分组并显示数量。首次优先显示需要处理，其次进行中，再其次已完成；之后记住上次分组。时间、日期和批次筛选保留，搜索框在分组旁，跨所有分组搜索；⌘F 定位搜索，搜索框内按 Esc 清空搜索并恢复筛选。状态列合并步骤进度，交付显示文件数；点表头排序，也可在列表页顶部操作栏选择最近构建等排序。多选后在底部操作条或右键菜单执行批量操作，访达入口在右键菜单中。顶部批量横幅可展开详情、调整并发、暂停或继续，并清除已完成记录。

项目页保留「概览 / 规划 / 编辑 / 交付」四个标签。已完成的项目默认进入编辑，其余进入概览。编辑页左侧选择截图、封面介绍或设计说明，右侧查看大图和编辑文字，文字改后自动保存。每屏下方只有一个「修改」入口：选「图和文字」或「只改文字」，输入要求后修改，留空按原要求重做；含图时先确认费用，历史及备选图入口保留。用时在概览查看，交付页显示最新、更新中或待更新及原因。项目页顶部固定显示软件名、状态和操作栏，窗口变窄时自动换行；左上角返回按钮或 ⌘[ 回到列表，⌥⌘↑ / ⌥⌘↓ 切换相邻项目。在访达中打开、改软件名、提交标记和移除放在「更多」；「从头重做」也在「更多」中，确认后归档旧内容再重新处理，代码来源不变；「批量修改」可从更多菜单打开，概览显示待处理意见。

试用版项目页测量：先用 `open=<试用项目路径>` 打开项目，`projectTab=editor` 切到编辑页；`editorScreen=<从零开始的序号>` 定位截图。该指令只在试用版改变当前选择，不调用模型或修改项目文件，配合 `probe` 记录延迟。


### 批量修改

项目列表的「批量修改」和项目页「更多 → 批量修改」打开同一个窗口。先选项目范围，可粘贴名单添加或移除；再逐条加入修改意见。只有一个项目时可指定某一屏、全部截图、封面介绍或设计说明，也可让软件判断。旧意见、编辑、删除、位置调整和已处理历史都保留。

整理前会提示文字模型费用；预览中可以排除动作、修改指令、切换单屏的图或文字，以及为未定位的意见指定位置。第三步确认后才加入批量队列。取消不会执行修改，已加入清单的意见会保存；未定位或只执行部分动作的意见留在项目概览，可继续处理。尚未保存的文字会在关闭前提示。

代码材料可不动、按各自模板重排、平均分配或统一模板，仅作用于已有交付包的项目。只重写文字和从头重做会调用收费模型，确认页会说明处理范围；它们不执行意见清单。PDF 随交付包自动更新，不再提供手动重新导出按钮。
