# 原生版快速入门

本文面向 `native/` 下的 SwiftUI macOS App。

## 1. 安装与检查环境

从 [GitHub Releases](https://github.com/deepfry666/ruanzhu-guide/releases) 选择原生版，下载 ZIP、解压并将「软件指南生成器.app」放到「应用程序」。

- App 最低运行版本：macOS 26。源码构建见[项目首页](../README.md#从源码构建)。
- 当前构建为 ad-hoc 签名，不应视为已经过 Apple 公证。若系统拦截，先核实发布者和下载来源，再按 macOS 的安全提示自行决定是否允许打开，不要关闭系统整体安全保护。
- 指南 PDF 需要 LibreOffice。在「设置 → 通用」查看检测状态，安装后可点「重新检测」。
- Word 代码模板的代码 PDF 使用原生排版；旧 TXT 代码模式转 PDF、导入 `.doc` 模板仍需要 LibreOffice。
- 在「设置 → PDF 与字体」检查可用字体和替代方案。不要从不可信来源下载字体，商业字体需有相应授权。

## 2. 配置模型与线路

### 生图线路

进入「模型与线路」添加生图线路，按服务商实际接口填写地址、模型、密钥及相应预设。不同服务的请求格式、图片尺寸和并发限制可能不同，不要只凭模型名称判断兼容。

首次使用以较低并发跑一个项目，确认返回结果、速度和费用后再批量处理。真实生图测速会发出生成请求，可能扣费。

### 大模型

添加厂商后，在「各步骤使用的模型」为下列任务选择模型并保存：

| 步骤 | 需要什么能力 |
| --- | --- |
| 规划界面 | 文字理解与结构化输出 |
| 截图验收与内容抄录 | 看图能力，能读取图片与图中文字 |
| 撰写说明文字 | 文字生成与结构化输出 |
| 设计说明（可选） | 文字生成与结构化输出 |

「测试」会调用接口并检查输出，不是免费额度保证。接口能连接不代表模型能正确完成看图或返回完整 JSON。

没有配置看图模型时，需要人工逐张确认图片；有看图模型也仍应人工核验最终内容。

### 注意费用与隐私

计费由你配置的服务商决定，软件不附送模型额度。模型测试、生成、重写、重试、图片重生与超时补发都可能产生费用；取消请求不一定撤销服务端计费。

生成所需的提示词、项目文字或图片会发送到所配置的服务商。只使用获准处理的数据。API 密钥只填在应用的配置界面，不要写进项目说明、截图、GitHub Issue 或共享日志。

## 3. 准备代码材料

当前版本提供「设置 → 代码模板」模板库，支持导入自己的 Word 模板；`.doc` 导入会借助 LibreOffice 转换。模板不随软件附带。

- 模板须来自你有权使用、且与目标软件材料相符的代码，不应拿无关模板证明软件实现。
- 当前 Word 模板模式按 A4、60 页、每页 50 个打印行排版；折行和空行计入打印行，不足要求或不支持的复杂结构会被拒绝。以应用校验结果为准。
- 超出模板页数要求时会选取相应片段，不代表代码完整性或登记合规已经审核。
- 可为新项目分配模板，也可在「项目」中「更新代码材料…」。这个操作不调用 AI。
- 在「设置 → TXT」核对开发环境、运行环境、编程语言和源程序量。当前模板路径有固定默认字段，**源程序量并非自动实测统计**；不要直接把默认值当作目标软件的真实信息。
- 旧项目的源码文件夹 / TXT 代码来源模式与 Word 模板模式规则不同。

## 4. 先做一个项目

1. 点击「项目」工具栏的「新建」（或在任意页面按 ⌘N），选择「单个」，填写软件名（可带版本号）、截图数、重点功能与补充说明。
2. 检查内容日期、最早日期和截图样式。内容日期用于生成内容，不是软件开发或交付事实的证明。截图样式也不是应用实际运行平台的证明。
3. 初次尝试建议在「设置 → 通用」打开规划确认，再点「创建并开始」。否则默认流程可能直接继续生成并调用付费接口。
4. 核对规划是否符合真实软件，再继续。图片生成后查看验收结果；自动判断不可靠时按真实情况人工核对。
5. 在「编辑」逐屏检查图片和说明。直接编辑文字会自动保存，不调用模型。需要模型处理时，使用每屏下方的「修改」：选择「图和文字」或「只改文字」；填写要求后按要求修改，留空按原要求重做。含图的操作会先提示图片费用，可取消；旧图和文字仍可从历史恢复。
6. 到「交付」打开生成文件，检查排版、字体、正文和代码材料，然后再导出。

应用所称的「截图」由生成模型绘制，并非从你的实际软件自动截取。若材料要求真实运行截图，应使用真实软件采集并按要求整理，不能把生成图当作实机证据。

## 5. 批量前的核验清单

- [ ] 软件名、版本、功能、日期与实际软件一致。
- [ ] 每张图的文字可读，数据和操作逻辑合理，无虚构功能或未经授权的信息。
- [ ] 说明文字与实际软件、配图内容相符，不只是通过模型验收。
- [ ] 代码来源有权使用，且与目标软件相符；TXT 字段不是未经检查的默认值。
- [ ] 在实际使用的阅读器里打开 Word 和 PDF，检查分页、字体、图片和可读性。
- [ ] 已确认服务商收费、并发限制、自动重试和补发设置。
- [ ] 已备份项目与重要材料，再执行批量覆盖或更新。

检查单个项目后，再使用新建弹窗的「批量」或「项目」的多选操作。批量「全部重做」会重新规划、出图和写文字，可能产生较多费用；「只重写文字」也会调用大模型。「已提交」项目保持只读，需要修改时先取消该标记。

本工具提供生成与排版辅助，不构成法律意见，也不保证软件著作权登记或其他审核通过。

## 常见问题

| 情况 | 先检查 |
| --- | --- |
| 提示没有密钥、鉴权失败 | 检查对应服务的密钥、接口地址和模型权限，不要反复发起收费任务 |
| 模型输出不是有效 JSON | 查看「模型与线路 → 调用记录」详情；核对结构化输出支持、输出长度与服务商余额 |
| 提示额度不足 | 先核查服务商账户额度或更换已授权线路 |
| 图片停在待确认 | 检查是否未配置看图模型，或自动验收后仍需要人工处理 |
| PDF 转换失败或字体警告 | 检查 LibreOffice 检测结果和「PDF 与字体」设置，再打开输出文件核验 |
| 代码模板被拒绝 | 检查打印行数和模板结构；复杂表格、图片、修订或段内换行可能不被支持 |
| 项目无法编辑或重跑 | 检查是否标为「已提交」，或仍在运行 / 排队 |

报告问题时请提供版本号、操作步骤和脱敏后的错误信息。日志可能包含模型返回或项目内容，分享前检查并移除密钥与私人数据。

## 文件、备份与旧版迁移

- 默认工作区：`~/Desktop/软件指南生成`，可在设置中更改。
- 原生版数据目录：`~/Library/Application Support/软件指南生成器（原生版）`。项目文件和应用数据不是同一个目录，备份时需分别考虑。
- 旧图片、文字历史和部分被替换的材料可在项目历史或 `archive/` 中找回，但不能把历史保留机制当作完整备份。
- 腾出磁盘空间：「设置 → 清理空间」先扫描、按类显示能腾出多少，勾选并确认后才清理，内容都移到废纸篓。默认勾选的是各项目里旧流程留下的 `tmp`、`scripts`、`lib`、`tests`、`debug` 文件夹和工作区根目录下旧流程的 `node_modules`、`tmp`、`tools`；超过 30 天的旧截图、手改保留的旧文件默认不勾选，清理后不能再从「以前的截图」换回。截图、规划和文案、交付包、30 天内的归档不会被动，运行中和排队中的项目会跳过。
- 原生版密钥使用本地加密文件保存，加密密钥也在同一应用数据目录；这不等于目录泄露后仍安全。不要公开、上传或随意共享此目录。

## 开发时试用新版

用 `native/scripts/trial.sh` 启动带「试用」标记的独立包，勿直接打开构建包。它将设置、成对密钥、模板和最近完成的三个项目复制到独立试用目录，工作区与正式版隔离，不继承队列或调用记录。可用 `--project <项目文件夹>`、`--count <数量>` 选项目，`--name <字母数字名字>` 隔离并行任务，退出试用版后用 `--reset` 重建副本。先 `--snapshot`，验证完成并退出后 `--verify` 核对正式文件是否变化。`--measure` 只复制全部状态和索引查看列表，不复制密钥或项目文件，也不运行步骤。验证只使用本机 receipt、build；AI 步骤须另行授权。详细参数见脚本 `--help`。

### 交付包自动更新

保存文字或 TXT 字段后，若只差本机步骤，约 3 秒后自动更新 Word、TXT 和 PDF，并检查 PDF 排版。连续保存会重新计时。更新时保留已完成分组，不计入项目运行用时。需要重新检查截图等 AI 步骤时，项目页显示原因和「继续」，由你决定是否运行。

无需再按「检查并更新」或「重新导出 PDF」；⌘R 可手动检查。打开交付文件、导出或打包 zip 会先等待更新，仍需 AI 的项目会被阻止或列入跳过清单。失败时查看项目页原因并点「重试」。交付包中手改的 Word / TXT 会先另存到 archive 的「手改保留」文件夹，再覆盖，并在项目页提示。退出时会等待本机更新结束。

开发测量可设置 `MS_DEV_CONTROL=<仓库外指令文件>` 后启动试用脚本。在指令文件里逐行写 `section=projects`、`stress=<每秒事件数>`、`scroll=1`、`probe=<仓库外结果文件>`，分别控制列表、模拟事件、自动滚动和延迟采样；用 `probe=stop` 写出统计，`stress=0`、`scroll=0` 停止模拟与滚动。自动滚动只在试用版生效，不调用 AI 或修改项目文件。试用版或开发控制启用时，标准错误输出包含读文件、解析、摘要、索引与设置和界面替换的耗时。结果和截图保存在仓库外。

项目列表按「需要处理 / 进行中 / 已完成 / 已提交」分组并显示数量。首次优先显示需要处理，其次进行中，再其次已完成；之后记住上次分组。时间、日期和批次筛选保留，搜索框在分组旁，跨所有分组搜索；⌘F 定位搜索，搜索框内按 Esc 清空搜索并恢复筛选。状态列合并步骤进度，交付显示文件数；点表头排序，也可在列表页顶部操作栏选择最近构建等排序。多选后在底部操作条或右键菜单执行批量操作，访达入口在右键菜单中。顶部批量横幅可展开详情、调整并发、暂停或继续，并清除已完成记录。

项目页保留「概览 / 规划 / 编辑 / 交付」四个标签。已完成的项目默认进入编辑，其余进入概览。编辑页左侧选择截图、封面介绍或设计说明，右侧查看大图和编辑文字，文字改后自动保存。用时在概览查看，交付页显示最新、更新中或待更新及原因。项目页顶部固定显示软件名、状态和操作栏，窗口变窄时自动换行；左上角返回按钮或 ⌘[ 回到列表，⌥⌘↑ / ⌥⌘↓ 切换相邻项目。在访达中打开、改软件名、提交标记和移除放在「更多」；「从头重做」也在「更多」中，确认后归档旧内容再重新处理，代码来源不变；「批量修改」可从更多菜单打开，概览显示待处理意见。

试用版项目页测量：先用 `open=<试用项目路径>` 打开项目，`projectTab=editor` 切到编辑页；`editorScreen=<从零开始的序号>` 定位截图。该指令只在试用版改变当前选择，不调用模型或修改项目文件，配合 `probe` 记录延迟。


### 批量修改

项目列表的「批量修改」和项目页「更多 → 批量修改」打开同一个窗口。先选项目范围，可粘贴名单添加或移除；再逐条加入修改意见。只有一个项目时可指定某一屏、全部截图、封面介绍或设计说明，也可让软件判断。旧意见、编辑、删除、位置调整和已处理历史都保留。

整理前会提示文字模型费用；预览中可以排除动作、修改指令、切换单屏的图或文字，以及为未定位的意见指定位置。第三步确认后才加入批量队列。取消不会执行修改，已加入清单的意见会保存；未定位或只执行部分动作的意见留在项目概览，可继续处理。尚未保存的文字会在关闭前提示。

代码材料可不动、按各自模板重排、平均分配或统一模板，仅作用于已有交付包的项目。只重写文字和从头重做会调用收费模型，确认页会说明处理范围；它们不执行意见清单。PDF 随交付包自动更新，不再提供手动重新导出按钮。
